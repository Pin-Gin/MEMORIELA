# Writing Rules

## 基本制作フロー
1. 妄想ログ0稿 — 台詞中心。まず場面を最後まで出す。
2. 演出稿 — `※` で場所、時間、動作、表情、視線、間を追加。小説文でなくてよい。
3. 小説初稿 — 作者の台詞・演出を尊重し、地の文へ変換。POVと場面情報を整理する。
4. QA — 初見読者、ストーリー、キャラクター、情報開示、POV、時系列、Knowledge Stateを確認する。
5. 完成稿 — 文体、読みやすさ、重複、表記を最終調整する。

## 第3話以降の執筆強化方針（試行）
- 第3話以降、一般的な小説作法とWeb小説としての読みやすさ・話の構築方法を改めて確認し、MEMORIELAに適合するものを作者が選択して取り入れる。
- 一般論をそのまま作品ルールにせず、「一般的な小説作法」「Web媒体で特に有効な作法」「流行・好み」「破っても問題ない慣習」を区別して検討する。
- 検討対象には、一文一義、一文・一段落の長さ、句読点、改行、会話文と地の文、視点、主語の省略、時制、描写と説明、場面転換、情報提示順、スマートフォンでの可読性を含める。
- 一話の構築では、話の役割、読者へ今回見せる情報、意味をまだ明かさない情報・伏線、まだ出さない情報、舞台情報、シーン構成、話の終了時に何が変化したかを大枠段階で確認する。
- 人物スポット回、日常回、転換回など、話の役割に応じて説明量・会話量・文章密度を変える。全話を同じ型にはめない。
- スマートフォン向けの文章長は現時点では未確定。50文字前後という案を含め、実際の執筆と実機確認で検証する。機械的な文字数分割はせず、長い文章は意味のまとまりを保って言い回しから再構成する。
- 構成QA → 0稿 → QA → 小説化 → スマートフォン可読性を含む通読・最終QA → 投稿、の流れを試行する。
- 数話運用して有効性を確認した後、MEMORIELA固有の正式な執筆・QAルールへ昇格する。
- 第2話は現時点で構成を再度崩さない。新方式が十分固まり、話数が進んだ後に、情報開示・必要な説明・文章構造・スマートフォン可読性などを新基準で再評価し、必要ならリファインする。

## 編集原則
- 会話のテンポと作者の意図を優先し、AIが勝手に美文化しない。
- 「気になる」と「分からない」を区別する。
- 意図した疑問・伏線は説明で潰さない。
- 場所、時間、話者、因果、知り得ない情報など、単純な混乱は修正対象。
- 表では軽い王道ラブコメ、掘ると行動に理由がある構造を守る。
- 違和感を置く → 日常として流す → 別の違和感 → 後で一本につなぐ。
- 情報は最初から置けるが、意味は後から明かしてよい。
- 全ての好みや行動に重い過去を付けない。
- 主軸POVは要・ゆら。ほかのPOVは、その人物の内面でしか得られない意味がある場合に限定する。

## ゆらの英語表現ルール
- ゆらと要が英語で会話する場合、台詞本文は日本語で表記し、`※英語で答える`、`※英語で返す` などの演出指定で、実際には英語で話していることを示す。
- 英文そのものは原則として本文に書かない。読者には会話内容を日本語で伝える。
- ゆらが要以外の人物に英語で話し、その人物が内容を理解できない場面では、ゆらの英語台詞を `――――` と表記する。
- `――――` で伏せた英語の内容は、必要に応じて要が日本語に訳すことで読者と周囲の人物へ伝える。
- ゆらの英語表現における `――――` は「英語で話しているが、その場の相手には内容が伝わっていない」ことを示す表現として扱い、小声・無音・聞き取れない台詞など別の意味には流用しない。
- ゆらの日本語力が上達した場合、英語へ切り替わる頻度や要による通訳の頻度も、その時点の言語能力と状況に合わせて変化させる。
