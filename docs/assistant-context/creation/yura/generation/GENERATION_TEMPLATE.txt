0. 固定前提
==================================================
YURAの正式MASTER画像と現行ビジュアルテキスト仕様を参照する。

固定事項:
- 久遠ゆら / YURA
- 成人女性、見た目年齢20代前半
- 身長153cm
- 7.25頭身を維持
- 小柄・華奢だが骨ばらない
- 体格比で胸はやや豊かめ
- 腕・脚の太さを生成ごとに変えない
- 銀白色のスーパーロングヘア
- 主な毛先は自然なウエストライン付近〜わずかに下
- 最長の細い毛先のみ上臀部手前まで許容
- 青灰色の瞳
- 高品質2Dアニメイラスト
- 衣装の露出は、指定された服種・シーンに対して通常の成人向け文脈に合う範囲を使用し、自動的な低露出化を行わない

MASTER / BODY / FACE / EYE SIGNATURE / HAIR v1.3 / Normal Super-Long / RENDERINGの保護仕様を、衣装・ポーズ・背景・余白より優先する。
髪型アレンジがある場合は `docs/assistant-context/creation/yura/identity/hair/HAIR_ARRANGEMENT_GUIDELINE.md` を併用し、元のスーパーロング長・総毛量を勝手に減らさない。
余白・アスペクト比・人物占有率は `docs/assistant-context/creation/yura/generation/framing/FRAMING_AND_MARGIN_SPEC.md` に従う。
用途別サイズ・比率・構図は `docs/assistant-context/creation/yura/generation/framing/IMAGE_SIZE_PROFILE_SPEC.md` の Profile A–E を選択し、BODY変形ではなく全体の均一スケール / 移動で調整する。

Hard rule:
- `GIT_VERIFIED` だけでは生成しない。
- YURA本人のidentity referenceは current Git MASTER、またはそのcurrent SHA-matched Bridge FULL + PORTRAITに限定する。
- 途中生成物 / rejected candidate / 過去派生 / chat memory / 3D参照をidentity referenceとして使用しない。
- tool-nativeな明示参照固定が信頼できる場合はapproved identity referenceだけを固定する。
- generator側の自動画像選択等によりMASTER以外のidentity混入を排除できない場合は `BLOCKED — REFERENCE INPUT NOT GUARANTEED` として生成しない。
- retryごとにこのPreflightをやり直す。
- rollback candidateはQA比較用であり、identity referenceへの再投入を意味しない。
- ユーザーが派生画像の利用を明示した場合も、その画像は指定されたderivative roleだけを持ち、YURA identity authorityはcurrent MASTERのまま。

==================================================

Post-operation exact pixel diff available?: yes / no

Hard rule:
- 差分なし / 変更なし / 維持 / 固定 / 寸分の狂いなし / 完全一致等では、未許可protected領域を生成変数にしない。
- whole-character text-to-image再生成で「同じ顔」「同じ髪」を狙う方式は禁止。
- immutable regionを再描画する可能性があるimage-to-image編集も禁止。
- exact-preservationを保証できなければ `BLOCKED — PROTECTED PIXELS CANNOT BE GUARANTEED`。
- 実行後はauthorized + dependency mask外のpixel delta = 0を検証する。
- 検証不能なら `REJECT — EXACT PRESERVATION NOT VERIFIED`。
- retryごとに0Aと0Bを再実行し、途中生成物をidentity sourceへ昇格しない。

==================================================

Can hidden / occluded BODY remain fixed in the geometry carrier?: yes / no

Hard rule:
- 服だけ / 髪だけ / 背景だけ / 表情だけ等のsingle-domain変更はBODY変更権限を与えない。
- 衣装maskがBODY投影領域に重なってもBODY geometryは別ロック。
- garment fits YURA; YURA does not change to fit garment.
- BODY geometry carrierがなく、hidden anatomyをgeneratorが再推測する必要がある場合は `BLOCKED — BODY GEOMETRY CANNOT BE GUARANTEED`。
- outfit-only exact-preservationでは `BODY_GEOMETRY_GUARANTEED` と `PROTECTED_PIXEL_PRESERVATION_GUARANTEED` の両方が必須。
- 実行後BODY equalityを証明できなければ `REJECT — BODY GEOMETRY PRESERVATION NOT VERIFIED`。
- retryは同じBODY geometry carrier / BODY_LOCKから行い、失敗生成物からBODYを引き継がない。

==================================================
11. 生成前確認
==================================================
Assistantは生成前に、上記入力を画像生成モデルが解釈しやすい文章へ整理して提示する。
Userが「OK」「その認識で合ってる」等で承認した後に生成する。

ユーザーが明示的に即時生成を依頼した場合は確認表示を省略できるが、CANON LOCK / protected domain rules / applicable Profile A–E / `GIT_VERIFIED` / `REFERENCE_INPUT_GUARANTEED` は内部で維持する。Exact-preservation triggerがある場合は `PROTECTED_PIXEL_PRESERVATION_GUARANTEED` も必須。いずれかを保証できない場合、即時生成依頼でも生成しない。

複雑ポーズでは、Assistantは必要に応じて以下を明示する:
- 安定案
- 少し複雑な案
- 破綻リスクの高い案

認識相違がある場合は生成せず、修正版を提示する。
